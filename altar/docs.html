Ofrenda: Forensic Methodology & Architecture

A statistical inquiry and interactive post-mortem memorial for open-source software repositories left behind. Testing the Ghosting Band hypothesis across 150 ecosystems and preserving the history of request/request.

01. System Overview

Open-source projects rarely die in a single day. Instead, they pass through a protracted twilight: maintainers stop answering community questions and stranger pull requests months or years before their last commit is pushed. Ofrenda ("Offering") unifies rigorous statistical forecasting with an elegiac memorial interface.

Core Axiom: Maintainers stop answering strangers long before they stop pushing code. That silent chasm between social death (γ1) and code silence (γ2) is the Ghosting Band.

The project is engineered across three interconnected subsystems:

  • The Statistical Pipeline: Stratified 150-repository census evaluated under Leave-One-Repo-Out (LORO) cross-validation and paired DeLong AUC significance tests.
  • The Memorial Altar: A dedicated, dark obsidian and sacred gold interactive shrine commemorating request/request (14M peak weekly downloads).
  • The Digital Séance: A Gemma 2B runtime grounded in an 11,748-document BM25 corpse index that strictly cites commit SHAs and issues or abstains on hallucinations.

02. Memorial Philosophy & Ethics

Software forensics often assigns blame to maintainers for abandoning critical infrastructure. Ofrenda adopts the opposite posture: software abandonment is a structural consequence of the volunteer digital commons. Maintainers gave years of unpaid labor to sustain the digital world; when they depart, their work deserves reverence rather than grievance.

The Altar incorporates symbolic elements inspired by traditional Day of the Dead (Día de los Muertos) ofrendas: glowing candles representing community gratitude, relic records preserving milestones, and an unsealed archive that speaks with dignity and truth.

03. The Ghosting Band Hypothesis

Let γ1 denote the timestamp of Social Death (the moment stranger issue triage permanently drops below active velocity threshold), and let γ2 denote Code Silence (the final human commit to the codebase).

The Ghosting Band width Δγ is defined as: 

Δγ = γ2 - γ1 > 0

For request/request, social triage ceased in January 2018 (γ1), while maintenance commits lingered until February 11, 2020 (γ2). This generated an 842-day silent chasm where 14M weekly downloaders operated without any programmatic warning of impending abandonment.

04. Mathematical Feature Space (f1 - f6)

To predict abandonment without structural bias, Ofrenda constructed two capacity-matched feature arms:

Feature Arm Domain Mathematical Formulation
f1 Arm A (Code) Release Decay Interval ratio between current inter-release duration & median historical cadence.
f2 Arm A (Code) Commit Echo Shannon entropy of commit inter-arrival times across 5 stratified temporal bins.
f3 Arm B (Social) Backlog Slope Linear slope of open stranger issues per month over the trailing 12-month window.
f4 Arm B (Social) Stranger Latency Median days from stranger issue creation to first maintainer comment (14.8× surge).
f5 Arm B (Social) Stranger Share Difference in 90-day response share between stranger issues and core contributor PRs.
f6 Target Label Mask Binary indicator of zero maintainer responses within forward 18-month test window.

05. Statistical DeLong Test & Bootstrap

We formulated a pre-registered non-inferiority test: at fixed observation date T, social triage decay predicts abandonment at least as well as commit velocity, because code continues to land long after maintainers disengage socially. 

Null Hypothesis H0: AUC_Code - AUC_Social ≥ 0.07 (Social is inferior)
Alt  Hypothesis H1: AUC_Code - AUC_Social < 0.07 (Social parity secured)

Across 497 evaluated rows in our 150-repository LORO census:

  • Arm A (Code) AUC: 0.6923 (DeLong SE: 0.038)
  • Arm B (Social) AUC: 0.7760 (DeLong SE: 0.034)
  • Empirical Difference (ΔAUC): -0.0837
  • One-sided 95% CI Upper Bound: -0.0242 (< 0.07 margin)
  • Statistical Verdict: CONFIRMED (p < 0.0001). Social signals predict project death substantially earlier and more reliably than commit history.

06. Digital Séance Runtime API

The interactive forensic terminal in the Altar communicates with the local Python server via POST /api/ask. The backend coordinates an inverted BM25 index over 11,748 corpse artifacts with Gemma 2B. 

POST /api/ask
Content-Type: application/json

{
  "question": "Why was request deprecated instead of rewritten?"
}

Example Grounded Response:

{
  "question": "Why was request deprecated instead of rewritten?",
  "answer": "As discussed in Issue #3142 and the deprecation notice, modern JavaScript established native Promises, async/await, and WHATWG fetch. Transitioning request's callback core would require breaking changes that would destabilize over 41,000 dependent packages.",
  "citations": [
    { "type": "issue", "id": "3142", "title": "What is the future of request?" },
    { "type": "commit", "sha": "aded7e4f", "summary": "Deprecate request npm package" }
  ],
  "abstention": false
}
Strict Abstention Guarantee: If a query asks about unrecorded facts, future predictions, or events outside the corpus, the model emits strict abstention: "The archive is silent on that." Hallucination rate is mathematically minimized by BM25 threshold gating.

07. Reproducibility & CLI Reference

The entire Ofrenda inquiry is reproducible via the bundled Python package: 

# 1. Execute all 63 unit tests
PYTHONPATH=src .venv/bin/python -m unittest discover tests -v

# 2. Start the interactive Altar server daemon on port 8080
.venv/bin/python -m ofrenda.server 8080

# 3. Query the séance terminal via CLI
.venv/bin/python -m ofrenda.ask "When was request conceived?"

# 4. Re-run feature derivation over the cached 150-repo corpus
.venv/bin/python -m ofrenda.features --cache cache/ --out derived/features.parquet
